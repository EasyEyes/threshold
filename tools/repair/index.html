Processed locally; originals remain unchanged.

For ranged trials, original values remain unchanged. Ranges cover fixation position and rendered-width rounding only. They exclude eye-tracker noise, viewing-distance error, timing error, and actual gaze deviation.

What happened?

With calibrateDistanceBool = TRUE (webcam distance tracking), EasyEyes used the logged eye point in the wrong coordinate frame.

Requested values were correct. In affected trials, drawn target position and size or spacing were wrong. Fixation was correct.

Repaired files receive a -repaired suffix. Already-repaired files pass through unchanged.

Statuses and output columns

targetEccentricityXDeg, targetEccentricityYDeg
Requested horizontal (x) and vertical (y) target position relative to fixation, in degrees.
thresholdParameter
QUEST-controlled input: spacingDeg (target–flanker spacing) or targetSizeDeg (target size), in degrees.
level
log10(input value / 1°).
  • corrected Exact recovered values replace requested values; repairImputedColumns lists replacements.
  • 2 candidates actualSpacingDegScenarioA and actualSpacingDegScenarioB store two spacings consistent with the logged triplet width.
  • approximate range approximateSpacingDegMin and approximateSpacingDegMax store approximate range endpoints, not guaranteed bounds; midpointSpacingDeg stores their midpoint.
  • needs review Evidence is insufficient; no value is imputed.

Ranged rows lack a unique recovered value and keep original values. Midpoints are summaries, not observations. Unaffected rows need no repair. Metadata are not trials. Unsupported target kinds lack a validated text-layout model.

Final threshold estimates are not recomputed. Re-fit them from trial responses and recovered levels.
